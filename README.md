# Bless Us — 検証用モック
Phaser 3（固定 CDN 3.90.0）＋純粋 JavaScript ES modules。Nuxt・バックエンド・ビルドなし。ゲーム仕様の正本は Drive のゲーム仕様.md。ここは試作の起動・仮定の記録。

## 起動
GitHub Pages: Settings → Pages → Deploy from a branch → develop / (root) → Save。相対パスで動作する。Actions は不要。main は受入前のため変更しない。
ローカル: `python -m http.server 8000` をリポジトリ直下で実行し http://localhost:8000/ を開く。Phaser CDN 接続が必要。
ホーム → ルーム → ルーム設定（人数・ラウンド数・初期体力・脱落時獲得率・初期デッキ・seed） → ゲーム開始 → 各ラウンドの選択・対戦・改変 → 対戦結果 → ルーム／ホーム。ホームからデッキカスタマイズ・音量設定へ移動できる。ルームでCPU／手動を追加・変更・退出でき、対戦中も個別に変更可能。CPUは自分のターンと自分が選択主体となる効果・能力・改変だけ自動操作する。手札は左右ドラッグでスクロールし、使用可能なカードを上の発動エリアにドロップして使用。対象カード・プレイヤーは強調表示された手札・プレイヤーから選択。発動中と直前のカード／能力を中央に表示。各トリガー・効果を個別行で表記し、処理中の効果行、単位・追加発動回数、前回効果の参照先とランダム抽選結果を表示（ランダム結果は処理ログにも記録）。CPUの一時停止・再開、全手札表示、ログJSON保存は検証用。設定・デッキはページ内保持（再読み込みで初期化）。初期デッキのカスタマイズは40〜60枚・各イベント1枚以上。標準デッキは50枚（仕様§10）。

## 確定仕様の実装・回帰検証
- §9.1: 発動元ごとの FIFO → 各プレイヤーの反応カード内順位 → 発動元所有者起点のターン順。登録済み順序を変更せず、発動時にいずれかの手札にあればその時点の所有者として発動。手札外なら失敗。ただし「捨てられた時」の反応に限り手札外でも発動し、手札外の場合は捨札時の所有者を発動主体とする。同一個体・各トリガーは1ターン1回。人工的連鎖上限なし。
- §5/9.3: 脱落後も手札保持とトリガー反応、体力変動と関連トリガーなし、任意対象から除外、脱落者が関与する体力交換は失敗。
- §6/9.3: 複数対象効果はターンプレイヤー起点で未集約単位を処理し、ドロー不足分は不発。§8/9.3: 直前のイベントカードは履歴参照対象だが効果なし。
- §4: ラウンド終了時の追加はランダムなアクションカードと任意のイベントカードを別選択肢にする。アクションカードは終了ラウンド番号と同数のトリガー・効果を個別抽選（トリガーは全12種類まで、数値効果は加算、非数値効果は重複除外）。能力による効果追加は別途適用。
- §7: 能力は原則ゲーム中永続、重複可能、獲得順。ターン終了時に他全員に1ダメージの能力は脱落中も発動し、ラウンド終了時に喪失。
- 実行: Node.js で `node test.mjs`。画面のブラウザ検証とは別。

## 試作の仮定（確定仕様ではない）
- 同一端末の2〜6人、既定4人（手動1・CPU3）/3ラウンド、先手をラウンドごとに交代。HP上限なし、同点は同率勝者。通信・ルームサーバーなし。
- 発動元カード単位で効果を最後まで適用してから反応群を登録順に処理。複数トリガーが反応した個体は各トリガーごとに登録。通常処理はターンプレイヤー起点。ターン開始→ドロー→権利獲得→反応解決、終了時カード反応→終了時能力（各能力のダメージ連鎖を解決）→権利0。脱落ターンは通常の開始・終了トリガー・終了時能力と能力獲得判定のみ（手札トリガーが通常どおり反応するとの仕様から導出）。
- 捨札イベントは移動前に反応登録し、移動後に解決する。初期配札ではドロートリガーを発生させず、通常ドローでは引いたカードも判定する。
- 発動履歴はラウンド単位で、発動時の効果を保存。初回の前回参照は不発。コピーは新個体（イベントのみ発動済み）。重複融合はトリガー集合和、数値効果は加算、非数値は1個。能力の5%重複は独立加算、追加発動は再抽選しない。
- 脱落はHP0の時点、連鎖終了後にラウンド終了。全滅は脱落順で得点。初期手札変更は配札後、各プレイヤーはターン順、能力は獲得順。候補不足時は存在する候補だけを提示。ターン外の権利は当該プレイヤーに保持。
- 選択時は全生存者（自分含む）を提示。体力交換の差分は体力増減として扱う暫定実装。
